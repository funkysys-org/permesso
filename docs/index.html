# 0 — installi (da PyPI)
$ pip install permesso

# 1 — firmi il permesso per il tuo target
$ permesso authorize --target www.tuosito.it \
    --owner te@esempio.it

# 2 — scansioni (il gate verifica la firma)
$ permesso scan --target www.tuosito.it \
    --plain-language --lang it --out report.html

# 3 — controlli cosa è cambiato, ogni notte
$ permesso diff scan-old.json scan-new.json

Come funziona

Tre passi, un solo principio.

Un binario, nessuna dipendenza runtime, tutta la configurazione su file leggibili. Funziona da CLI, in CI e dentro i tuoi agenti AI.

1

Autorizzi

Firmi un permesso per il target: perimetro, titolare, scadenza. È una firma HMAC su file — niente permesso, niente scansione: il gate blocca prima di un solo pacchetto di rete.

2

Scansioni

Controlli passivi integrati (header, TLS, cookie) più nuclei, testssl.sh, ssh-audit e Lynis quando disponibili. Licenze verificate: il GPL gira solo come processo esterno.

3

Capisci e sistemi

Ogni rilievo dice «cosa significa» in linguaggio umano e come sistemarlo, con le evidenze. Report HTML brandizzabile, in italiano o inglese.

Cosa c'è dentro

Piccolo, verificabile, onesto.

Le funzioni sono quelle di un prodotto finito, non di un esperimento.

✍️

Gate di autorizzazione firmato

Firma HMAC, perimetro, scadenza, rigetto di manomissioni. Testato contro 6 casi d'abuso.

🔎

5 adattatori di scansione

Passivo integrato, nuclei, testssl.sh, ssh-audit, Lynis. Gli strumenti mancanti compaiono nel report come «non eseguiti», mai silenziosi.

🗣️

Linguaggio umano, IT/EN

Ogni rilievo è tradotto in impatto reale e azione concreta. Pronto per un livello LLM opzionale.

🌙

Modalità continua

diff tra scansioni: nuovi, risolti, invariati. Exit code per allarmi automatici quando compare un problema grave.

Agent-native
