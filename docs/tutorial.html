Tutorial

Dal primo permesso al primo report, in dieci minuti.

Tutto ciò che segue l'ho fatto davvero, comando per comando. Copia, incolla, e alla fine hai un report che un non esperto sa leggere — e un monitoraggio che parte ogni notte da solo.

0

Requisiti

Linux o macOS con Python ≥ 3.10. Nessuna dipendenza Python, nessuna API key. Su Debian/Ubuntu basta pipx:

sudo apt install pipx git pipx ensurepath # poi riapri il terminale
1

Installa e fai il check dell'ambiente

pipx install permesso permesso doctor

doctor mostra cosa è pronto e cosa manca, con i comandi di installazione pronti per la tua piattaforma. Un tool mancante non rompe mai la scansione: finisce nel report come "skipped", alla luce del sole.

2

Autorizza il tuo target

Il gate è il prodotto: firmi un permesso con perimetro, titolare e scadenza. Senza permesso valido, permesso esce prima di inviare un solo pacchetto.

permesso keygen permesso authorize --target www.tuosito.it --owner tu@email.it --days 30

Con --scope domain il permesso copre anche i sottodomini. File manomesso o scaduto → "UNAUTHORIZED", exit 2.

3

Prima scansione

permesso scan --target www.tuosito.it \ --validate --plain-language --lang it --out report.html

Otterrai due file: report.html (quello che consegni) e il JSON della scansione (quello che rileggi). In console:

scan complete: 8 finding(s) (C:0 H:0 M:2 L:4 I:2) report: report.html json: scan-www.tuosito.it-20261127-120000.json
4

Leggi il report

In cima: i conteggi per gravità e la validazione. Ogni rilievo dice "Cosa significa" in italiano, il rimedio concreto e le evidenze. I rilievi con il badge ✓ sono stati riverificati con una seconda osservazione indipendente; i transitori (non riprodotti) vengono evidenziati, non spacciati per reali. I controlli che non hai potuto eseguire sono elencati: mai una promessa silenziosa.

5

Siti WordPress: tutto automatico

Se il target è WordPress non configuri niente: permesso enumera versione core, plugin (referenze nella pagina + slug popolari via readme.txt) e temi; controlla utenti esposti via REST, debug.log e backup di wp-config verificati nel contenuto; poi incrocia le versioni con il database CC0 di wpvulnerability.net. WPScan non serve — né la sua licenza commerciale.

6

Monitoraggio continuo

monitor salva lo storico, confronta ogni run col precedente e restituisce exit 10 quando compaiono nuovi problemi gravi — perfetto per cron, CI o una mail d'allerta:

# crontab -e 17 3 * * * permesso monitor --target www.tuosito.it \ --validate --plain-language --lang it permesso portal # pagina cliente + console dallo storico

Lo storico vive in ~/.permesso/history/<host>/ — sul tuo disco, come tutto il resto.

7

Branding e consegna (per agenzie)

Metti nome, colore e footer della tua agenzia nel report che consegni al cliente; il PDF si esporta con un comando se hai Chromium o wkhtmltopdf:

cat > branding.json <<'EOF' {"agency_name": "La tua agenzia", "logo_text": "La tua agenzia · Security", "accent_color": "#7c2d12", "footer": "Report riservato al cliente.", "language": "it"} EOF permesso scan --target www.cliente.it --branding branding.json --out report.html permesso pdf report.html
